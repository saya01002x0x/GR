# ✅ Setup Checklist - Onboarding Guide

## 🎯 For New Developers

Checklist to get your development environment running in **< 15 minutes**.

---

## Step 1: Prerequisites ✅

- [ ] Docker Desktop installed & running
- [ ] Git installed
- [ ] Node.js 18+ (optional, for local scripts)
- [ ] Code editor (VS Code recommended)

---

## Step 2: Clone & Setup ✅

```bash
# Clone repository
git clone <your-repo-url>
cd GR

# Run automated setup script
# Windows:
.\setup-env.ps1

# Mac/Linux:
chmod +x setup-env.sh
./setup-env.sh
```

**Manual alternative:**
1. Copy `backend/env.template` → `backend/.env`
2. Copy `frontend/env.template` → `frontend/.env`
3. Fill in required values (see `docs/ENV_SETUP.md`)

---

## Step 3: Get API Keys ✅

### Required (Must Have)

- [ ] **Clerk API Keys** (Auth)
  - Sign up at https://clerk.com
  - Create application
  - Get `CLERK_SECRET_KEY` & `CLERK_PUBLISHABLE_KEY`
  - See: `docs/CLERK_SETUP.md`

### Optional (Can Skip for Now)

- [ ] Meilisearch API key (auto-generated by Docker)
- [ ] MinIO keys (auto-generated by Docker)
- [ ] SMTP settings (Mailpit in Docker, no config needed)

📖 **Full guide:** `docs/API_KEYS.md`

---

## Step 4: Start Services ✅

```bash
# Start everything with Docker Compose
docker-compose up -d

# Wait 30 seconds for services to initialize
# Check logs
docker-compose logs -f backend
```

**Expected output:**
```
✓ [NestFactory] Starting Nest application...
✓ [NestApplication] Nest application successfully started
```

---

## Step 5: Verify Services ✅

### Backend API
- [ ] http://localhost:3001 → "Hello World!"
- [ ] http://localhost:3001/artworks → JSON response

### Frontend
- [ ] http://localhost:3000 → Landing page

### Supporting Services
- [ ] http://localhost:7700 → Meilisearch dashboard
- [ ] http://localhost:9001 → MinIO console (admin/password123)
- [ ] http://localhost:8025 → Mailpit (email testing)
- [ ] http://localhost:5050 → pgAdmin (admin@admin.com/admin)

---

## Step 6: Test Authentication ✅

### Manual Test

```bash
# 1. Create test users (inside backend container)
docker exec -it gr-backend npm run script:create-users

# 2. Get JWT token
docker exec -it gr-backend npm run script:get-token

# 3. Test protected endpoint
curl http://localhost:3001/artworks/me \
  -H "Authorization: Bearer YOUR_TOKEN_HERE"
```

### Thunder Client (VS Code)

1. Install Thunder Client extension
2. Import `thunder-client-collection.json`
3. Update bearer token in requests
4. Run tests

📖 **Full guide:** `docs/TESTING_QUICK_START.md`

---

## Step 7: Development Workflow ✅

### Hot Reload Enabled ✅

Code changes auto-reload in Docker containers:
- Backend: `npm run start:dev` (watch mode)
- Frontend: `npm run dev` (watch mode)

### Create New Feature

```bash
# Generate module
docker exec gr-backend npx nest g module modules/my-feature
docker exec gr-backend npx nest g controller modules/my-feature
docker exec gr-backend npx nest g service modules/my-feature
```

### Check Logs

```bash
# All services
docker-compose logs -f

# Specific service
docker-compose logs -f backend
docker-compose logs -f frontend
```

### Restart Service

```bash
docker-compose restart backend
docker-compose restart frontend
```

## 🐛 Common Issues

### Port Already in Use

```bash
# Check what's using port
netstat -ano | findstr :5432

# Stop conflicting service or change port in docker-compose.yml
```

### Docker Build Fails

```bash
# Clear cache and rebuild
docker-compose down
docker-compose build --no-cache
docker-compose up -d
```

### Backend Won't Start

```bash
# Check logs
docker-compose logs backend --tail=100

# Common fixes:
# 1. Missing CLERK_SECRET_KEY in backend/.env
# 2. Syntax error in code (check logs)
# 3. Port conflict
```

📖 **Full troubleshooting:** `docs/COMMON_ERRORS.md`

You're ready to code when:

- ✅ Can create test users & get JWT token
- ✅ Protected API endpoints work with token

## 📋 Quick Commands Reference

```bash
# Start all services
docker-compose up -d

# Stop all services
docker-compose down

# Restart service
docker-compose restart backend

# View logs
docker-compose logs -f backend

# Run backend command
docker exec -it gr-backend npm run <command>

# Enter backend shell
docker exec -it gr-backend sh

# Database access (when Prisma added)
docker exec -it gr-backend npx prisma studio

# Format code
docker exec -it gr-backend npm run format
```
