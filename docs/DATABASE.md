# TASK: DATABASE SCHEMA GENERATION (PRISMA & POSTGRESQL)

**Role:** Senior Backend Engineer & Database Architect.
**Project Context:** "ArtSpace" - A Pixiv-style artwork sharing platform.
**Tech Stack:** NestJS (Backend), Prisma ORM, PostgreSQL, MinIO (Object Storage).

## 🎯 OBJECTIVE
Generate a complete, production-ready `schema.prisma` file based on the requirements below.

---

## 1. CORE ENTITIES & REQUIREMENTS

### A. User (Người dùng)
* **Purpose:** Stores user identity (synced with Clerk/Auth) and profile details.
* **Fields:**
    * `id`: String (UUID) - Primary Key.
    * `clerkId`: String (Unique) - Mapping to external Auth provider.
    * `email`: String (Unique).
    * `username`: String (Unique).
    * `displayName`: String (Nullable).
    * `avatar`: String (Nullable) - Stores MinIO URL.
    * `bio`: String (Nullable).
    * `role`: Enum (USER, ADMIN). Default: USER.
    * `isArtist`: Boolean. Default: false.
    * `preferences`: Json? - For settings (e.g., `{ "r18": true, "theme": "dark" }`).
* **Relationships:**
    * `artworks`: One-to-Many (Author).
    * `comments`: One-to-Many.
    * `likes`: Many-to-Many (or explicit table).
    * `followedBy`: UserFollows (Followers).
    * `following`: UserFollows (Following).

### B. Artwork (Tác phẩm)
* **Purpose:** The main content entity.
* **Fields:**
    * `id`: String (UUID) - PK.
    * `title`: String.
    * `description`: String (Text).
    * `type`: Enum (ILLUSTRATION, MANGA). Default: ILLUSTRATION.
    * `status`: Enum (DRAFT, PUBLISHED, ARCHIVED). Default: PUBLISHED.
    * `isAI`: Boolean (AI-generated flag). Default: false.
    * `isR18`: Boolean (Sensitive content). Default: false.
    * `viewCount`: Int (Default 0).
    * `likeCount`: Int (Default 0).
    * `commentCount`: Int (Default 0).
    * `createdAt`, `updatedAt`: DateTime.
* **Storage Strategy (MinIO):**
    * Since a Pixiv-like post can contain multiple images (Manga pages), DO NOT store a single URL.
    * Use a separate model `ArtworkImage` to store pages.
* **Relationships:**
    * `author`: Many-to-One (User).
    * `images`: One-to-Many (ArtworkImage).
    * `tags`: Many-to-Many (Tag).
    * `comments`: One-to-Many.
    * `likes`: One-to-Many (Like).
    * `bookmarks`: One-to-Many (Bookmark/Collection).

### C. ArtworkImage (Ảnh chi tiết)
* **Purpose:** Handle multiple images per artwork (e.g., Manga pages or variations).
* **Fields:**
    * `id`: String (UUID).
    * `url`: String - Full URL to MinIO object (e.g., `http://minio:9000/artworks/abc.jpg`).
    * `order`: Int - To sort pages (0, 1, 2...).
    * `width`: Int? (For layout calculation).
    * `height`: Int? (For layout calculation).
* **Relationships:**
    * `artwork`: Many-to-One.

### D. Tag (Thẻ)
* **Purpose:** Categorization and Search.
* **Fields:**
    * `id`: String (UUID).
    * `name`: String (Unique).
    * `count`: Int (Usage count).
* **Relationships:**
    * `artworks`: Many-to-Many.

### E. Social Interactions
1.  **Comment:** User + Artwork + Content (Text).
2.  **Like:** User + Artwork (Composite Key to prevent duplicate likes).
3.  **Bookmark:** User + Artwork + (Optional) `collectionName` (Private bookmarks).
4.  **Follow:** `followerId` (User) + `followingId` (User).

---

## 2. MINIO STORAGE INTEGRATION NOTE
* The database **DOES NOT** store binary data (BLOB).
* All image fields (`User.avatar`, `ArtworkImage.url`) must be type `String`.
* These strings will store the public URL generated by the NestJS Storage Service pointing to the MinIO bucket.
